# B-606 progress (caret lands inside a trailing `[[link]]` on click-right / End)

Branch: `worktree-agent-ad349bb7b38028773` (based on main `07720d1`). Not merged into main.
Status: fixed, verified (see below). Commits listed in the last section.

## Cause (measured, two of them, one per gesture)

Spec `e2e/tests/caret-after-link.spec.ts`, run on the pre-fix sources (fix reverted, same spec):
20 failed / 8 passed across Chromium + WebKit. Measured values on `plain text [[Balení]]`:
click right of text then `Y` stored `plain text [[BaleYní]]`; Home, End, `Z` stored
`plain text [[BaleníZ]]`.

1. **Click on the rendered (not-yet-editing) block** — `caret.ts#resolveClickOffset`. The hit test
   answers `(text "Balení", 6)` inside `<a data-from=11 data-to=21>`; the mapping added the
   rendered offset to `data-from`, which is the `[[`, so it landed at 17 = `[[Bale|ní]]` (two
   characters early, and never past `]]`). Same for `**bold**` (inner span's `data-to`, before
   `**`) and `((ref))` (rendered text is another block's; landed inside `((id))`).
2. **End (and a click inside the editor)** — `livePreview.ts` hides `]]` with a zero-width
   `Decoration.replace`. With `EditorView.lineWrapping`, CM6's `moveToLineBoundary` finds the line
   end by `posAtCoords(editor right edge)`
   (`node_modules/@codemirror/view/dist/index.js` `moveToLineBoundary`, 6.43.11), which can never
   return a position past a zero-width range, so it answered `targetEnd` (before `]]`). That
   position "touches" the link, so the `]]` was revealed and typing went into the target. Home
   before a leading link mirrored it (`[[ACAL Lead]]`). CM6's mouse selection uses the same hit
   test: clicking right of the text in the editor gave `[[BaleníW]]`.
   `atomicRanges` does not help: a caret AT the edge of an atomic range is not inside it.

`#[[multi word]]` was already fine (rendered verbatim, markers never hidden); kept as a guard.

## Fix

- `apps/web/src/editor/caret.ts`: a point with nothing rendered after it on its line maps to the
  `data-to` of the outermost element around it that also ends there (after `]]`, after `**`);
  symmetric for the line start (`data-from`). Inside a `.vr-block-ref` the outermost ref element is
  what maps (its preview's nested offsets are the target block's). Mid-link characters now count
  from `data-text-from` (= `targetStart`, set on un-aliased wikilinks in `render/tokens.tsx`).
- `apps/web/src/editor/livePreview.ts`: `livePreview` is now an extension array. Home/End and
  mac Cmd-ArrowLeft/Right (and Shift variants) at `Prec.high` wrap CM6's own line-boundary
  commands and then move the head across hidden markers that start (End) / end (Home) exactly
  there, using the markers hidden BEFORE the move. A `transactionFilter` does the same for a
  `select.pointer` cursor when only hidden markers lie between it and its line's end/start.
  Math widgets (non-zero width) are excluded.
