# B-609 — a zero-delay Enter/Tab burst on a brand-new journal day loses the Tab

Branch: `worktree-agent-a1a8803e8c967f3b2` (based on main `4c28fad`). Status: **fixed, verified**
(see Verification). Not merged to main.

## Cause (two, both with evidence)

"A brand-new day" covers two different components, and the burst `aaa`⏎`bbb`⇥⏎`ccc`⇧⇥ broke
each for its own reason. Evidence came from an e2e diagnostic that logged every `keydown`'s target,
`focusin`/`focusout`, the rendered rows each animation frame, and (temporarily) every `BlockTree`
commit and page-tree effect run.

### 1. The sweep's own case: today's page exists with no blocks (`BlockTree`'s "Start typing…")

`indent-render.mjs journal` deletes today's top-level blocks first, so the page exists and the day
is a real `BlockTree` showing `.vr-empty-start` — not the draft. Trace on the base (zero delay):

```
COMMIT block.create            <- click on "Start typing…"  (aaa's block)
FETCH [] local=["0:"]          <- page-tree effect re-run, NOT a new fetch
COMMIT block.create            <- Enter (bbb)
FETCH [] local=["0:aaa","0:"]  -> rows become ["0:"]   (aaa gone from the tree)
keydown Tab                    <- no COMMIT at all: bbb has no sibling above
COMMIT block.create            <- Enter (ccc)
FETCH [] local=["0:bbb","0:"]  -> rows ["0:cc"]
FETCH ["aaa","bbb",""]         <- the real refetch, much later; server: aaa,bbb,ccc all depth 0
```

The page-tree effect in `BlockTree.tsx` tracks `editingId()`, so every Enter re-runs it against
the **last fetch** (here: the empty page). It rebuilt `localBlocks` from that fetch and kept only
the *edited* block among this tab's not-yet-fetched creations (`unseenCreations`). The block above
was dropped, so Tab had nothing to nest under and wrote nothing, and the rows flickered down to the
one being edited until the real refetch came back — the sweep's `["","ccc"]` flicker is the same
dropped state. An ordinary page did not show it because its existing (fetched) block stays above.

### 2. The draft (`VirtualJournalDay`): a page with no page at all — `/journals` today, `/page/<date>`

Found while reproducing; not what the sweep hit, and worse (text lost, and a button pressed):

```
focusin textarea.vr-draft-input
keydown a,a,a,Enter,b,b,b -> textarea      (prepare() still out: Enter only closes the line)
keydown Tab -> textarea ; focusout textarea ; focusin button.help-fab
keydown Enter -> button.help-fab            (presses Help)
keydown c,c,c -> button.help-fab            (lost)
keydown Shift+Tab -> back to the textarea
server: aaa, bbb   (no ccc, no nesting)
```

The burst arrives ~10 ms after focus, before `prepare()`'s two worker round trips (template + HLC
pool), so Enter takes B-411's "keep the keys in the textarea" path — and the textarea let Tab do the
browser default, moving focus out of the day.

## Fix

- `apps/web/src/editor/BlockTree.tsx` (page-tree effect): every block this tab created that no
  fetch has returned yet (`unseenCreations`) is kept from the local tree, not only the edited one.
- `apps/web/src/views/VirtualJournalDay.tsx`: while the draft holds the keys, Tab/Shift+Tab are the
  outliner's (default prevented; nest under the line above, at most one deeper; first line can't
  nest), lines carry a depth (`DraftLine`), drawn with `--depth`, and `dayOps` writes the nesting
  (`parentId` + per-parent order). Backspace at the start of a waiting line joins it to the line
  above (else a stray Enter in a burst becomes an empty block).

## Still unverified

- The 60 ms/key flicker was **not reproduced** in the e2e graph either before or after (both
  paths, 60 ms/key: rows never dropped). It was seen on the 952-page real graph, where fetches are
  slower. Cause 1 explains a flicker of exactly that shape (rows collapse to the edited one until the
  real refetch answers), and that state can no longer arise, but no run on the real graph was done.
- A *seen* block's structure change (Tab on an existing block) followed by Enter is still re-run
  against the last fetch and could show the old place until the refetch answers. Not observed; not
  in scope (would need a pending-ops overlay over fetches). Candidate bug if seen.
- The draft's teardown path (B-243, `keepUncommittedDraft`) still appends waiting lines flat: depth
  typed in a draft torn down by another device's write is lost (text is kept).
- Tab no longer moves keyboard focus out of the draft (as in the outliner itself).
