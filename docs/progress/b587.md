# B-587 progress (HLC order vs seq order on a name collision)

Branch: `worktree-agent-aea25230c5fee842c` (based on main `c897962`). Not merged into main.
Commits: `0cb4a62` (fix + tests + ADR 026), and a follow-up commit with the HTTP probe, wording

## Question settled: it IS a convergence bug, not only a verify false alarm

Deterministic test `apps/web/src/sync/e2e.test.ts` "a page created under a name the server freed,
with an HLC older than the freeing op, converges on every replica (B-587)": real server, real
`SyncClient`s. A's clock runs 5 s behind (a deterministic stand-in for "same millisecond, before A
heard of the delete"; ADR 003 rejects only clocks running *ahead*), so A's `page.create` has an
older HLC than the server's `refpages` `page.delete`, and a later seq. On `c897962`:
`expected [ 'C', 'D' ] to deeply equal []`.

- C (bootstrapped before the delete, then ONE incremental pull of delete + A's ops): no live
  "Ghost Name" at all, A's block missing — lost for good.
- D (one pull of the whole log from 0): A's page and block present, old page's tombstone missing.
- A, B (live, one push/pull at a time) and E (snapshot afterwards): match the server.
- Old `verify` replays the same way (HLC sort) → reports divergence; the original same-millisecond
  shape reports A's page and block `missing-in-rebuild` (`tools/probes/b587-hlc-order-name-collision.ts`).

Cause: `SyncClient.pull()` and `verifyRebuildParity` handed a server-log batch to core `applyOps`,
which re-sorts by HLC; a collision check then met state the server never showed that op.

## Fix (ADR 026, `docs/adr/026-server-log-applied-in-seq-order.md`)

`applyOps(driver, ops, { order: "seq" })` (new `ApplyOpsOptions`; default stays `"hlc"`) applies a
batch as given. Used by `SyncClient.pull()`, `SyncClient.applyPushResponse()` (corrections) and
`verifyRebuildParity`. Matches `docs/spec/sql-schema.md` rule 26, which already said `seq` order.
Rejected (costs in the ADR): server re-stamps the late op (cascades to every dependent op, ids are
HLCs, `name_hlc` diverges on the author), server rejects it (loses a legitimate write),
order-independent name ownership (much larger, cycle check still order-dependent), fix verify only
(hides C's lost page).
