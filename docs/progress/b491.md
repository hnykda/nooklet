# B-491 — no native dialogs (window.confirm/alert/prompt) in the web client

Branch: worktree-agent-a6081d106880ccaf6 (based on main 94543a8). Status: done, one commit (see
`git log`), not merged.

## What changed
1. `app/confirm-dialog.tsx`: `acknowledgeOnly` option + `noticeDialog(title, message)` — a one-button
   in-page alert built on the existing `confirmDialog`.
2. `views/HistoryView.tsx`: Undo and Restore this version ask through `confirmDialog`
   (confirm labels "Undo" / "Restore").
3. `app/refactor-host.tsx`: "Turn into page / Move to page / Merge page failed" → `noticeDialog`.
   Not the title-row notice: Turn into page and Move to page also run from the journals stream,
   which has no title row. Closes the palette first; the notice is not awaited.
4. `views/PageView.tsx`: "Rename failed" → `announce(…, true)`, the existing title-row notice
   (`app/page-actions.ts`). `views/PageActions.tsx`: that notice is `role="alert"` when it is an
   error (was always `role="status"`).
5. `views/GraphMismatchView.tsx`: inline `<p class="connect-error" role="alert">`.
6. `plugins/host.ts`: `ctx.confirm` → new `deps.confirm`, wired to `confirmDialog` in
   `plugins/ClientPlugins.tsx` (plugin message as the dialog title, OK/Cancel). `ctx.prompt` stays
   unsupported: no in-page text-input dialog exists, and building one is not trivial.
7. Guard: `src/source-guards.test.ts` "native dialogs (B-491)" — fails on `window|globalThis|self
   .alert|confirm|prompt` or a bare `alert(`/`confirm(`/`prompt(` call anywhere in `apps/web/src`
   (comments, strings, `x.confirm(` and typed method signatures excluded). Checked against the
   pre-fix sources: it flags all four old call sites. A grep test rather than biome
   `noRestrictedGlobals`, because that rule does not see `window.confirm` member access.
