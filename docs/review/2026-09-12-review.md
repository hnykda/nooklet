# Code review, 2026-09-12

Brief from the owner: "make a review of the code and improve it, as is now. No backward compat or
anything, just as clean as it can be given we are starting this. Security should not be a
post-thought, but also doesn't have to be absolutely bulletproof given this is already mostly for
local use or something behind a VPN."

This document is the working record: what was read, what was found, what was changed, and what was
deliberately left. Defects get a `docs/BUGS.md` entry (B-52 and B-53 onward — B-43 was taken by a
concurrent fix while this review ran) and a test; cleanliness is summarised here rather than logged one by one.

### Defects found (evidence first)

| # | Severity | Where | What |
|---|---|---|---|
| B-53 | high | `ops/search.ts` | The raw query string goes straight into `block_fts MATCH ?`. Probe (`tools/probes/fts5-query-syntax.mjs`): `c++`, `what's`, `a.b`, `e-mail`, `foo -bar`, `"unbalanced`, `(` all throw → HTTP 500 / MCP `internal`. The description promises `-exclusions`; FTS5 parses `-bar` as a column filter. Also `updated_after: "yesterday"` silently returns nothing (`Date.parse` → NaN). |
| B-54 | medium (security) | `http/app.ts#webClientToken` | Every server start mints a new `write`+`can_sync` token labelled `web-client (auto)` and never revokes the previous one. The doc comment claims a restart invalidates old sessions; it does not. The owner's real graph had three live ones. |
| B-55 | medium | `ops/page-update.ts`, `apply-ops.ts` | `page.update keep_alias` writes `page_alias` with a raw INSERT — outside `serverApplyOps`, invisible to other devices and to `rebuild()`. Nothing else ever populates `page_alias`, so an imported `alias::` property (which the spec, rule 6, says MUST refresh it) never resolves: `page_read("Old Name")` 404s. |
| B-56 | medium | `ops/changes-since.ts` | `classify` treats any `block.delete`/`page.delete` op as a deletion. `batch_undo` of a delete mints `block.delete {deletedAt: null}` — a restore — and `changes_since` reports it as `block.deleted`. The `*.restored` kinds in the schema were never produced. |
| B-57 | medium | `ops/schemas.ts`, every write op | `batch_undo`'s input says its `batch_id` comes "from a previous write's response", and the README promises an agent can undo any batch it just made — but `WriteResult` has no `batch_id`; the undo tests fished it out of `changes_since`. `page_create` with markdown was two batches, so undoing "the" batch emptied the page and left it. |
| B-58 | medium | `ops/registry.ts`, `ops/schemas.ts` | `idempotency_key` is accepted on every write, described as "returns the original result instead of applying it twice (stored 24h)", and `page_append`'s description tells agents to rely on it for retries. Nothing reads it. A retried `page_append` duplicates blocks — precisely the case the field exists for. |
| B-59 | medium | `mcp/stdio.ts` | Uses `scopesFor(verified.scope)` instead of `allScopesFor(verified)`, so a `--ui-control` token over the stdio bridge (Claude Desktop) never gets `ui:control`; the five `ui_*` tools are missing there. `tokens.ts` documents that every caller must use `allScopesFor`; this one was missed. |
| B-60 | low | `live/registry.ts`, `live/live.ts` | A `state.result`/`command.result` frame resolves whichever pending request carries its `request_id`, regardless of which socket sent it — an unauthenticated socket that never sent `hello` can still answer. `unregisterWindow`'s doc says it fails the window's in-flight requests immediately; it does not, callers wait out the 2 s timeout. |
| B-61 | low (security) | `http/assets.ts`, `ops/asset-upload.ts` | Assets are served with the uploader's `mime_type` verbatim and no `X-Content-Type-Options`/CSP. A `text/html` (or scripted SVG) upload executes in the app's origin. A `mime_type` with a newline made `new Response` throw → 500. `readFileSync` of up to 25 MB blocks the event loop per request. |
| B-62 | low | `ops/page-list.ts` | `tag` filter is `pp.value LIKE '%tag%'` on the raw `tags::` string: `tag: "art"` matches `party` and `smart`; `[[Art]]` and `#art` forms depend on the literal text. ADR 017's `page_tag` table exists for exactly this and was not used. |
| B-52 | low | `data-api.ts#journalDayFromWire` | `2026-13-45` passes the regex and becomes journal day `20261345`; `page_append` then creates a page under that name. |
| B-63 | low (security) | `plugins/routes.ts`, `plugins/server-context.ts` | `registerRoute(app)` mounts a plugin's whole Hono sub-app under `/api/plugins/<id>/` with no authentication, and `rpc.expose` mounts unauthenticated POST routes — reachable from the LAN when `--host` is set. The handler form defaults to `auth: "required"`; the other two forms silently did not. |

Verified-not-a-bug, worth recording:

- `batch`/`dry_run` hold a SQLite savepoint across `await`s while `serverApplyOps` fires
  `notifyCommit` (a WebSocket poke) *inside* it. A `/sync/pull` handled between those awaits would
  read uncommitted ops. It cannot happen today because every write handler is microtask-only (no
  real I/O inside a trial), so no macrotask — an incoming request — can interleave. This works by
  construction rather than by design; noted in `ops/trial-lock.ts` so the invariant is written down.
- `web-client.ts` still injects the token into `index.html` although B-19 moved the client to
  `/api/session`. Harmless (same token, `no-cache`, loopback only) and the e2e specs read
  `window.__NOOKLET__` to seed data, one of which is being edited concurrently — left alone.
- `@modelcontextprotocol/hono`'s own Host/Origin guard is still merged at `/` behind nooklet's, so
  when bound to loopback an unknown `Host` gets 403 on the SPA fallback and `/mcp` but 200 on
  `/healthz`. Inconsistent, not exploitable; comments updated to say what actually runs.

### Cleanliness (no individual BUGS entries)

- `apply-ops.ts`: `void tokenizeContent;` and its import — a "reserved for later" that never came.
- `formatDayTime`/`formatDoneIso` duplicated three times (`data-api.ts`, `apply-ops.ts`,
  `mirror/export.ts`) and again as `dayToIso`/`doneTimestamp` in the web editor, plus the
  property-flattening logic duplicated between `rowToBlock` and `snapshotBlock`. The duplication in
  `apply-ops.ts` is apologised for in a comment ("to avoid a circular import"). Fixed by moving the
  two formatters into `@nooklet/core` (`task-dates.ts`) and the row mappers/snapshots into
  `packages/server/src/rows.ts`, which neither `data-api.ts` nor `apply-ops.ts` depends on the
  other for.
- `isoFromJournalDay` was an alias of core's `isoJournalName` "kept as a separate name because the
  two are different ideas that merely happen to agree". Since ADR 018 they are the same idea.
- A fake `Page` object (`{ key: "", properties: {}, createdAt: 0, … }`) built in four ops purely to
  call `wirePageName`, plus two private helpers doing the same lookup — one `pageWireNameById`.
- `data-api.ts`: `QueryApi.semantic` and `unlinkedRefs` were stubs returning `[]` with a comment
  saying embeddings "ship in M3" (M3 shipped). `PagesApi.create({firstBlock})` applied two separate
  batches (not atomic). Header said `@nooklet/plugin-api` "does not exist yet".
- Stale headers describing a codebase that no longer exists: `ops/registry.ts` ("plugin-api does
  not exist yet"), `ServerConfig.allowedHosts` (the MCP library's guard "is installed app-wide"),
  `sync/realtime.ts` + `sync/index.ts` ("today only `push.ts` calls `notifyCommit`" — every write
  does, via `serverApplyOps`), `http/assets.ts` ("that file is being edited concurrently"),
  `mcp/server.ts#mountMcp`, `data/api-client.ts` ("device pairing isn't built yet"),
  `sync/http-transport.ts` ("`/sync/*` routes are being built concurrently"), `data/store.ts`
  (backlinks "not wired into the invalidation bus" — they are, since B-09; and `useOpenTasks`'s doc
  comment sits above `useFavoritePages`), `plugin-api/server-context.ts` ("no plugin host exists"),
  `plugins/manifest.ts` ("not yet built").
- `cli.ts` re-implements `isLoopbackName`.
- `ops/search.ts`: a `pages.length > 20` check the schema already enforces.
- `ops/changes-since.ts`: a hand-written 11-member union cast where the Zod enum already exists.

### Tests that don't test

- `live/rpc.test.ts` proved request/response correlation but never that a *different* socket

- `ops.http.test.ts` covered `page.list` by namespace and kind but not by `tag`, so B-62's substring

## Pass 3 — left alone, and why

- **Token injected into `index.html`** (see above): removal touches `e2e/tests/editing.spec.ts`,
  which another agent owns this session.
- **`verifyToken` writes `last_used_at` on every request**, including reads. Fine at this scale
  under WAL; a throttle would be premature.
- **`/sync/live` and `/ui/live` accept a socket that never sends `hello`** and keep it open
  indefinitely. Local/VPN deployment; a handshake timeout is cheap but not urgent.
- **Asset ids are guessable-ish** (45 bits of time + 25 random bits) and `/assets/:id` is
  unauthenticated by necessity (`<img>` cannot carry a bearer). Acceptable behind loopback/VPN;
  documented in `http/assets.ts`.
- **`embeddings.configure` fetches any URL a write-token holder supplies** (SSRF-shaped). The
  caller is the owner's own client; not a boundary worth adding ceremony to.
- **The editor** (`BlockTree.tsx`, `commands.ts`, `history.ts`): read carefully, found sound. The
  pure ops layer is well-tested and the DOM-facing bugs in BUGS.md are covered by e2e. Files under
  `commands/autocomplete`, `commands/slash`, `CommandLayer.tsx`, `editor/surface.ts` are being
  edited concurrently (B-42) and were not touched.
- **Client-side alias resolution** (`usePageByName` looks up `key` only): `page_alias` is a
  server-only table; the client would need to scan `page_prop.alias`. Logged as a follow-up in
  B-55 rather than done here.
