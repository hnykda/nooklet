type:: guide
summary:: What nooklet import reads from a Logseq file graph, what it changes on the way in, and what it leaves behind.
tags:: guide

- `nooklet import <graph-dir> [--data <dir>]` reads a classic Logseq **file graph** — `pages/*.md`, `journals/*.md`, `assets/`, `logseq/config.edn` — into a nooklet data directory (ADR 012). It does not read the Logseq DB version's markdown export (different layout, a page-level `id::` line, no `config.edn`); that would be new scope, not an extension.
- Try it on a data directory you can throw away first: `pnpm nooklet import /abs/path/to/graph --data /tmp/trial`, then `pnpm nooklet serve --data /tmp/trial` and look around. When happy, import into the real one (default `~/.nooklet/default`). The graph path must be absolute when running through `pnpm nooklet` ([[Command line]]); a directory that does not exist imports zero pages with no error.
- The result is printed as JSON: pages, journals and blocks imported, pages skipped, dangling block references, assets copied, dangling asset links, a `warnings` list and an `errors` list. Read both: an error is one file that did not import, and the rest of the graph did.
- ## What carries over
  - **Pages**, named from the file name. Triple-lowbar (`A___B___C.md` → `A/B/C`) and the older `%2F` encoding both decode; a `title::` property overrides the file name. The pre-2022 "dot" encoding (`A.B.C.md`) is deliberately not decoded — it cannot be told from a literal dot. Two files that resolve to the same name: the first wins, the second is skipped with a warning.
  - **Journals**, from `journals/YYYY_MM_DD.md` (or `YYYY-MM-DD`), stored under the ISO date. The graph's `:journal/page-title-format` is reported and offered as the display format ([[Journals]]). A journal file with an unrecognised name is imported as an ordinary page, with a warning.
  - **Blocks**: tabs, two spaces or four, `id::` lines, `collapsed::`, continuation lines, code fences, headings inside blocks (`heading:: N` becomes a `#` prefix), numbered lists (`1.` bullets and `logseq.order-list-type:: number` become `list:: number`), `*` and `+` bullets, bulletless paragraphs, YAML front matter, CRLF line endings. Every block gets a fresh 14-character id.
  - **Properties** on pages and blocks. Keys are lower-cased and `_` becomes `-`; `custom_id` becomes `id`. Values stay strings. `tags::` and `alias::` become page tags and aliases ([[References and tags]]).
  - **References**: `[[links]]`, `#tags`, `#[[multi word]]`, `[label]([[Page]])`. `((uuid))` block references and `{{embed ((uuid))}}` are rewritten to the new ids — every Logseq UUID is mapped in a first pass over the whole graph, so cross-page references resolve. A reference whose target is not in the graph is left as written and counted in `danglingBlockRefs`. A duplicate `id::` (which Logseq repairs lazily) keeps the first block; references resolve to it, with a warning.
  - **Tasks**: `TODO DOING DONE LATER NOW WAITING CANCELED`, with `WAIT`, `CANCELLED` and `IN-PROGRESS` normalised; `[#A]` priorities; `SCHEDULED:` and `DEADLINE:` lines, with weekday, time and any of the three repeater spellings, become `scheduled::`, `deadline::` and `repeat::`. `LATER` and `NOW` stay as they are ([[Tasks]]).
  - **Assets**: every file in `assets/` is copied into the data directory's asset store, content-addressed, and every `](../assets/name.png)` or `](assets/name.png)` link is repointed; names with diacritics match across macOS's NFD file names and Logseq's NFC markdown. A link whose file is missing stays as written and is counted in `danglingAssetLinks`. Without `--data` the importer still runs but warns that assets had nowhere to go.
  - **config.edn**: only `:journal/page-title-format`, `:journal/file-name-format` and `:file/name-format` are read, and only the first has any effect (both file-name encodings are accepted regardless). Favourites, default templates and everything else in `config.edn` are ignored.
  - **History**: each imported page and block takes `createdAt` from its file's modification time and is attributed to the `logseq-import` actor under its own device id, so `changes_since` can tell imported content from later edits.
- ## What does not
  - `:LOGBOOK:` drawers are dropped entirely (ADR 011): time tracking is a non-goal, and state changes from now on live in the op log.
  - `{{query ...}}` and Datalog blocks, `{{renderer}}`, `{{cloze}}`, tweet and video macros, any other `{{macro}}`: kept as literal text, nothing runs them. `#+BEGIN_QUOTE` … `#+END_QUOTE` stays as text; `> ` quotes render.
  - PDF highlights (`hl-*` properties) are kept as ordinary properties with nothing rendering them. Whiteboards, flashcards and the Logseq DB version's features are not imported and not planned.
  - Templates, favourites, the graph's settings, plugins: not imported.
  - Block text is never rewritten beyond ids and asset paths: `[[Mon, 07.09.2026]]` stays as typed and resolves anyway ([[Journals]]).
- ## Re-importing
  - The importer creates pages; it does not merge into existing ones. A page whose name already exists is skipped with an error naming the file. To re-import, start from a fresh data directory or delete the pages first. (ADR 004 says the UUID mapping is kept in an import table so a re-import is idempotent; the importer keeps the mapping in memory only, and no such table exists.)
- Verified against a real graph: 952 pages, 17.5k blocks, Czech and English, heavy task use (`docs/PLAN.md` §2; `packages/server/src/importer/verify-real-graph.manual.ts`).
