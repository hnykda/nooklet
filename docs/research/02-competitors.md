# 02 — Competitor survey: what to copy, what to avoid

*Research date: 2026-09-10. Sources: shallow clones of silverbullet, siyuan, Trilium, AFFiNE, anytype-heart, any-sync, athens (all at HEAD on 2026-09-07..10) under `scratchpad/repos/`, plus GitHub pages, official docs and release notes. ## 2. SilverBullet — study this one hardest

Repo: https://github.com/silverbulletmd/silverbullet · docs: https://silverbullet.md · 6.0k★, 479 forks, MIT, v2.10.0 (July 2026), 323 open issues, one primary author (Zef Hemel). Local clone: `scratchpad/repos/silverbullet` (docs live in `docs/`, ADRs in `docs/Architecture/ADR/`).

### 2.1 Stack and its history
- **Client**: TypeScript, CodeMirror 6, Preact, ESBuild; Node 24 toolchain, vitest (migrated from Deno in 2.6.1).
- **Server**: **Rust** as of 2.10.0. The progression was Node → Deno (2022–2025) → Go (2.1.2, Sep 2025, "significantly less memory") → Rust (2.10.0, mid-2026, converging with the commercial SilverBullet+ Tauri desktop app). Rationale in ADR-008/010 and the blog post "On Tech Stacks" (https://no.silverbullet.plus/tech-stacks): minimize the number of technologies, prefer maturity, seek leverage (Tauri binaries, Rust CRDT ecosystem), keep it fun. Deno's package-management churn was a recurring pain.
- **Space Lua**: a from-scratch Lua 5.4 interpreter written in TypeScript (`client/space_lua/`). ADR-005: v1 had *three* end-user languages (a query language, Handlebars templates, "Space Script" JS); v2 unified them into one Lua dialect with "Space Lua Integrated Query" (`query[[ from p = index.pages() where ... select ... ]]`). Writing their own interpreter bought deep interop, code completion and jump-to-definition. Admitted cost: "We likely lost users over this" (hard v1→v2 break).

### 2.2 Architecture (ADR-001/002/003/007)
Three layers, `docs/Architecture.md`:
1. **Client** (one per tab) runs "90%+ of the logic": editor, Space Lua runtime, plugs, syscalls, the IndexedDB-backed datastore and the **Object Index**.
2. **Service Worker** (one per browser): caches the client, hosts the **sync engine**, and *implements the HTTP API locally* by intercepting `/.fs` calls — so the app behaves identically online and offline.
3. **Server**: "only three jobs: handle authentication, serve the (static) client code, and implement the HTTP API (list/read/write/delete files, run shell commands)… effectively a file store."

ADR-007 (2025-08-29) is the key decision: v1 had a server-side plug runtime *and* a client one ("server mode" vs "sync mode"); maintaining two PlugOS runtimes in parity was "a persistent burden" and a source of subtle bugs, so v2 **eliminated the server runtime** — "sync mode becomes the only mode". Consequences they list honestly: memory dropped from "a few hundred MB to single to low-double digits", server became trivially swappable (hence the cheap Go/Rust rewrites), but **every client must sync the full space and rebuild its own index** (cold-start cost, no thin-client option for big spaces or weak devices), and "server-authoritative features are harder — notably real-time collaboration/CRDT merging".

### 2.3 Sync (ADR-002, `client/spaces/sync.ts`, `client/service_worker/sync_engine.ts`, `server-merge/`)
- File-level, bidirectional, implements the unterwaditzer 2016 sync algorithm (snapshot of `(localMtime, remoteMtime)` per path, plus recorded remote revision hash and last common base hash). Full-space scan every ~20 s (60 s when the realtime channel is healthy), open file every 2–3 s; a `/.events` stream carries remote revision hashes so changes appear "within ~2–3 s".
- Writes carry `If-Match: "sha256:<hash>"`; a `412` routes into **three-way reconciliation**: client posts `{baseText, proposedText}` to the server, which runs a line- and word-aware `diff3` (Rust crate `server-merge`) and returns `applied | merged | conflicted | retry`. Unresolvable conflicts are written **into the file** as `<<<<<<< SB sha256:…` markers and rendered as a conflict widget in the editor (it also understands git's `<<<<<<< HEAD`). Binaries / files > 1 MB get a `name.conflicted-<hash>.ext` sibling.
- "A deletion never silently wins over a concurrent edit" — modification wins, deletion suppressed and surfaced as a notification.
- `documents` (non-markdown attachments) are *not* synced by default (fetched on demand); `sync.ignore` takes gitignore patterns.
- CRDT was tried and removed (real-time collab PR 411, 2023, "too many edge cases"); ADR-002 says the Rust backend "reopens the CRDT path" but it's deferred. Collaboration doc is explicit: "This is not Google Docs… two people typing into the same paragraph at once is the case this design handles worst."
- **Revisions** (2.10): git-backed history maintained by the server (managed/unmanaged/disabled), commits per author, optional push/pull to a remote as backup with a conflict-review UI.

### 2.4 Index and object model (ADR-003)
Every markdown element (page, header, item, task, paragraph, link, tag, table row, `data` YAML block, and since 2.9 a generalized `relation`) becomes an *object* with tags and attributes in an IndexedDB object index. Indexing is event-driven (`page:index`), per-page and concurrent ("an indexer must never resolve one page's markup against another page's index entry… joins belong at query time"). The index is a cache: `Space: Reindex` rebuilds it; schema changes force a full resync + reindex on every device. Query lag of a few seconds after edits is documented. Full-text search is **not** in core (separate "Silversearch" library). 2.4's "indexer rework" gave 2× speed; paragraph indexing is off by default to save storage.

### 2.5 Extension model
- **Plugs**: `*.plug.yaml` manifest + TS → single `*.plug.js` bundle; each plug runs in its **own Web Worker**; the only channel is `syscall(name, ...args)` (invoke main→worker, syscall worker→main). Permissions are declared in the manifest (`shell`, `fetch` are gated; everything else open). Hooks: commands, slash commands, events, message queue, code widgets, document editors. Loaded from anywhere in the space; `Plugs: Reload` hot-reloads. Built-ins (`plugs/editor`, `plugs/index`, …) use the same mechanism.
- **Space Lua** is now "the first-choice way to extend": `space-lua` fenced blocks in pages define commands, slash commands, widgets, templates, event handlers; runs on the main thread (a runaway script offers a "stop" after a couple of seconds). **Libraries** (meta pages, optionally wrapping plugs) are the unit of distribution, **Repositories** the discovery layer, installed via a Configuration Manager UI (2.7).
- Security stance: shell access off by default per space (2.10 edge), three access levels `none/read/write`, `write` "carries real trust".

### 2.6 HTTP API (`docs/HTTP API.md`)
- `GET /.fs` (listing with mtimes/perms, "primarily used for sync"), `GET/PUT/DELETE /.fs/<path>` with `X-Last-Modified`, `X-Created`, `X-Permission`, `X-Get-Meta`; `ETag: "sha256:…"`, `If-Match`, `If-None-Match: *`.
- `/.revisions/…` (git log/diff/content), `/.ping`, `/.shell`, `/.logs`, `/.proxy/<host>/…` (CORS proxy), `/.config`, `/.client/manifest.json` (dynamic PWA manifest), `/.accounts`, `/.spaces/api/…` (multi-space admin). Auth: JWT cookie or `Authorization: Bearer <SB_AUTH_TOKEN>`. `X-Sync-Mode: true` marks client requests.
- **Runtime API** (2.6, experimental): because *all* logic is client-side, external automation needs a *client*, so the server spawns **headless Chrome** running the full SilverBullet client and exposes `POST /.runtime/lua`, `/.runtime/lua_script`, `GET /.runtime/logs` over CDP; the `sb` CLI wraps it (`eval`, `script`, `query`, `describe`, REPL). A 2.8 REST `/.runtime/objects/*` was **removed in 2.10** because it "added too much complexity and another query language". No MCP server.

### 2.7 Mobile
PWA only ("Add to Home Screen"), full space in IndexedDB, works offline; there is no native app (SilverBullet+ is a separate paid Tauri desktop product). The editor is CodeMirror on a phone; 2.10 edge notes a batch of iOS fixes (pickers hide keyboard shortcuts on touch, filter boxes disable autocapitalize/autocorrect, top-bar colour on lost connection, setup wizard usable on a phone). Sync only runs while a tab/PWA is open and the browser keeps the service worker alive ("perhaps up to a minute" after backgrounding). Outlining is limited to `Outline: Move Up/Down/Left/Right` and fold commands — "not a proper outliner like LogSeq".

### 2.8 Lessons for vrite
1. **Keep the server dumb *for files* but not *for the index*.** SilverBullet's thin file-store server made offline-first and backend rewrites cheap, but pushing *all* indexing to the client forced the headless-Chrome Runtime API hack, cold re-indexing on every device, and no thin client. vrite should hold the canonical index (SQLite) on the server and let the PWA hold a local replica.
2. **Copy the conflict pipeline**: content hashes as ETags, `If-Match` on every write, server-side 3-way merge, conflicts written in-band with markers and rendered as a widget, deletions never beating edits. It is a pragmatic middle ground that works with external editors/agents/scripts writing the same files — a requirement vrite shares.
3. **One extension language, one query language** — SilverBullet's biggest v2 lesson (and its biggest migration pain). Decide early; don't ship three DSLs.
4. **Web-Worker sandboxes + syscall boundary + manifest permissions** is a proven client-plugin design; vrite can do the same in the browser and mirror it with worker threads on the server.
5. Avoid: excluding full-text search from core, paragraph-level indexing that has to be disabled for performance, breaking-change rewrites that lose users.

## 3. SiYuan

Repo: https://github.com/siyuan-note/siyuan · API: `docs/API.md` (2,880 lines) · formats: `docs/SY-FORMAT.md`, `docs/WORKSPACE.md` · 46.3k★, 3.0k forks, AGPL-3.0, v3.8.3 (Sep 2026), 27k commits. Paid: SiYuan Cloud sync/backup and some services; commercial use of the app is free. Local clone: `scratchpad/repos/siyuan`.

### 3.1 Stack
- **Kernel** in Go (`kernel/`): gin HTTP + WebSocket server, **Lute** (their own Go markdown/AST engine), SQLite (`siyuan.db` with FTS5, `blocktree.db`), `dejavu` snapshot repo, `kernel/mcp`, `kernel/plugin` (kernel plugins), `kernel/cli`, `kernel/agent`, `kernel/mobile` (gomobile bindings).
- **UI** in TypeScript (`app/src`): "Protyle" contenteditable block editor, separate `app/src/mobile` UI, Electron desktop; native iOS (Swift), Android (Kotlin), HarmonyOS shells embed the kernel and load the web UI. Desktop can now connect to a remote kernel (3.8.3).

### 3.2 Storage format (`docs/SY-FORMAT.md`, `docs/WORKSPACE.md`)
- One **`.sy` JSON file per document** = serialized Lute AST: root `NodeDocument` with `ID`, `Spec`, `Properties` (the IAL: `id`, `title`, `updated`, `icon`, custom attrs) and nested `Children`. Block types: `NodeParagraph`, `NodeHeading`, `NodeList`/`NodeListItem`, `NodeBlockquote`, `NodeCodeBlock`, `NodeTable`, `NodeSuperBlock`, `NodeAttributeView`, … Every block has a 22-char ID `YYYYMMDDHHMMSS-xxxxxxx` (timestamp + 7 random chars) and `Properties.updated`.
- **Filename is the ID; directory structure is the hierarchy**: `data/<boxID>/<docID>.sy` plus `<docID>/` for children, nested to arbitrary depth. Notebooks ("boxes") are ID-named dirs with `.siyuan/conf.json` and `sort.json`.
- `temp/*.db` are explicitly *rebuildable* caches; `data/storage/` holds attribute-view definitions; `repo/` and `history/` hold snapshots. The doc ranks the official write paths "HTTP API > MCP > CLI > direct `.sy` edits" and warns that direct edits require an index rebuild.
- SQL schema (`kernel/sql/database.go`): `blocks(id, parent_id, root_id, hash, box, path, hpath, name, alias, memo, tag, content, fcontent, markdown, length, type, subtype, ial, sort, created, updated)`, `spans`, `assets`, `attributes`, `refs(def_block_id, block_id, …)`, `file_annotation_refs`, an FTS5 external-content table over `blocks`, and **`block_embeddings(id, embedding BLOB, model, …)`** — embeddings are built into the kernel (OpenAI-compatible endpoint config, `SIYUAN_OPENAI_EMBEDDING_*` env; "SiYuan Agent and vector embedding search entered public testing" in 3.7).

### 3.3 Sync
- `dejavu` (https://github.com/siyuan-note/dejavu, AGPL): a git-like, content-addressed repo (SHA-1 indexes → files → deduplicated chunks; refs `latest` + tags), AES-encrypted with a user-held key, pushed to S3 / WebDAV / SiYuan Cloud. Conflicts are kept as history for manual review. Sync is snapshot-based (periodic or manual), with on-demand asset download (3.8.3) and a new **LAN sync** manager (`kernel/model/lan_sync.go`, native discovery on iOS/Harmony).
- README is blunt: it "does not support third-party sync disks" — putting `data/` in Dropbox/iCloud corrupts things. This is the cost of a many-small-JSON-files-plus-index design without per-file merge semantics.

### 3.4 API (`docs/API.md`)
- All endpoints are `POST /api/...` with JSON bodies, `Authorization: Token <token>`, response `{code, msg, data}`; the spec section carefully states that `code: 0` does **not** imply indexes/WebSocket/sync have caught up and that idempotency is per-endpoint.
- Groups: notebooks, documents (create with markdown, rename/move/remove, hpath↔id lookups), assets, **blocks** (`insertBlock` / `prependBlock` / `appendBlock` anchored by `nextID > previousID > parentID`, `updateBlock`, `deleteBlock`, `moveBlock`, `foldBlock`, `getBlockKramdown`, `getChildBlocks`, `transferBlockRef`), attributes (`setBlockAttrs`/`getBlockAttrs`), attribute-view databases (render/get/search/set cell/filter/sort/fields), search, **`/api/query/sql`** (raw SQL over the index — the most loved power feature; disabled in publish mode), templates (Sprig), files, export (markdown, zip), pandoc, notifications, forward proxy (JSON/HTTP/WS/SSE), system. `/api/transactions` is internal.
- Block insert returns the same `doOperations` transaction the UI uses (`{action:"insert", data:<DOM>, id, parentID, previousID}`) — one op vocabulary for UI, API and undo.

### 3.5 MCP, CLI, kernel plugins (3.7, mid-2026)
- **Built-in MCP server** at `/mcp` (`kernel/mcp/server.go`, official Go MCP SDK, streamable HTTP, protocol version `2026-07-28`), gated to admin role; tools mirror the API: `block`, `document`, `notebook`, `search`, `sql`, `ref`, `tag`, `dailynote`, `database`, `outline`, `todo_write`, `template`, `file`, `asset`, `export`, `import`, `history`, `repo`, `sync`, `inbox`, `web_fetch`, `web_search`, `question`, `skill`, `system`, `workspace`. Each tool declares "effects" (`localRead`, `localWrite`, …) per action.
- **Kernel plugin system**: a plugin's `kernel.js` runs **inside the Go process** on **goja** (Go JS engine) with an event loop per plugin (`kernel/plugin/plugin.go`, `sandbox.go`); injected `siyuan.*` API: `plugin`, `event`, `logger`, `storage`, `rpc`, `client`, `server`, `secrets`, and `agent.registerCapability(name, {inputSchema, effects}, handler)` which *publishes the plugin function as an MCP tool*. Rationale from the release notes: "plugins run resident in the kernel as a single source of truth, keeping every window and instance consistent". Hot-reloads on `kernel.js` change.
- **Frontend plugins**: `plugin.json` + `index.js`, class `Plugin` with `onload/onunload`, `addDock`, `addTopBar`, `addCommand`, `eventBus`, `Setting`, `protyle` hooks, breadcrumb buttons, custom block renderers; distributed through the `bazaar` marketplace (plugins, themes, widgets, icons, templates) with ratings.
- **CLI** (`siyuan-cli`, 3.7): drives the kernel without the GUI for batch import/export, SQL, sync.

### 3.6 Mobile
Native apps (iOS/Android/HarmonyOS) embed the Go kernel via gomobile and render the TypeScript mobile UI in a WebView — fully offline, same data model. 3.7 added "shorthands" (long-press the app icon to capture a timestamped note); 3.8.x has a steady stream of mobile fixes (keyboard/bottom-bar, safe areas, block selection, PDF annotation). Browser access to a docker-hosted kernel also works.

### 3.7 Lessons for vrite
1. **Kernel-as-single-source-of-truth**: one HTTP/WS API consumed by the desktop UI, mobile UI, plugins, CLI *and* MCP. This is exactly vrite's target shape; SiYuan proves it scales to 46k★ and daily releases.
2. **SQL over the block index** (`blocks`, `refs`, `attributes`, `spans`) is the killer power-user/LLM feature; expose it read-only over HTTP and MCP. Note SiYuan's careful "code 0 ≠ index updated" semantics.
3. **Block insert/move anchored by `previousID`/`parentID`, IDs that sort by time, and filename = ID** are clean primitives; but **avoid `.sy` JSON as the canonical format** — it is not human-editable, not markdown, and forces the "no Dropbox" rule. Keep markdown canonical, derive the index.
4. **Kernel plugins that can register MCP tools** (`agent.registerCapability`) is the most interesting 2026 plugin idea in the field; vrite server plugins should be able to do the same.
5. Avoid the feature surface (databases, flashcards, PDF, publish, cloud): it's why the kernel is 27k commits.

## 4. AFFiNE and BlockSuite

Repo: https://github.com/toeverything/AFFiNE · 72.4k★, 5.3k forks, MIT (Enterprise edition planned), v0.27.5 (Sep 2026; v0.27.4 Aug 2026), 11.5k commits on `canary`. Local clone: `scratchpad/repos/AFFiNE` (~2.7k TS files in `blocksuite/`, ~3.8k in `packages/`, **~867k lines** of TS/TSX/Rust).

- **Stack**: React + Jotai UI, Electron desktop, Capacitor iOS/Android (`packages/frontend/apps/{ios,android}`, plus `mobile-native` Rust via uniffi), NestJS + GraphQL + Postgres + Redis backend, Rust **`y-octo`** (Yjs-compatible CRDT, `packages/backend/native`), `nbstore` storage abstraction (IndexedDB / SQLite / cloud), Copilot AI.
- **BlockSuite** (`blocksuite/framework/{store,std,sync}`, `blocksuite/affine/*`): a block-editor framework on **Yjs** — a `Schema` of block "flavours" (`flavour`, `role`, `parent`/`children` constraints, `props`, `version`, transformer), reactive block models over Y.Map/Y.Text, Lit web-component views, `KeymapExtension`/`BlockViewExtension`/`WidgetViewExtension`. Docs generated by TypeDoc; the standalone BlockSuite site is de-emphasized in favour of in-repo use.
- **Sync** (deepwiki summary + `nbstore/README`): each doc is a Y.Doc; `DocSyncPeer` exchanges state-vector diffs, `BlobSync` moves attachments (multipart/presigned/GraphQL), `IndexerSync` builds search indexes in the background; server `SpaceSyncGateway` (Socket.IO, Redis pub/sub, version-specific rooms `sync`, `sync-026`, `sync-027`) stores updates in a Postgres `doc updates` table and squashes them into snapshots with y-octo. **Breaking lock-step**: "v0.27 clients require v0.27+ servers".
- **Plugins**: none public (an early plugin experiment was removed). **API**: GraphQL for the app; no simple notes REST or MCP.
- **Self-host**: Docker with Postgres + Redis; config moved from env vars to `config.json` in 0.27.
- **Lessons**: (a) Yjs-per-document + whiteboard + collab + AI is the ceiling of complexity — 870k LOC, three storage tiers, a Rust CRDT, and server/client version coupling; do not start here. (b) Data lives as Yjs binary; markdown is an export, so "your files" is weaker than it sounds. (c) Worth stealing: `nbstore`'s tiny storage interface (`getDoc`, `pushDocUpdate`, blob get/set, connection status) run *behind a worker*, and BlockSuite's **versioned block schemas with migrations**. (d) If vrite ever wants CRDT text, keep it per-block (Y.Text or Loro) with markdown still canonical.

## 5. Anytype (any-sync, anytype-heart)

Repos: https://github.com/anyproto/any-sync (MIT, 1.7k★), https://github.com/anyproto/anytype-heart (Go middleware, **"Any Source Available License 1.0"**), https://github.com/anyproto/anytype-ts (8.8k★, same license). Protocol overview: https://sync.any.org. Developer docs: https://developers.anytype.io. Local clones: `scratchpad/repos/{any-sync,anytype-heart}` (both committed within the last week).

- **Object model**: everything is an object of a **Type** with **Relations** (properties); objects contain a block tree; spaces are the unit of sharing; "system" types/relations carry a `Revision` for migrations; a middleware-maintained `backlinks` relation ("Links to this object") is updated by a watcher on link changes (`docs/Flow.md`). A newly rewritten **subscription engine** (`docs/SubscriptionsEngineDesign.md`) turns any filter/sort/window into a live query feeding the UI.
- **Changes**: `pb/protos/changes.proto` defines the op vocabulary — `BlockCreate`, `BlockUpdate`, `BlockMove`, `BlockRemove`, `DetailsSet/Unset`, `RelationAdd/Remove`, `ObjectTypeAdd`, `StoreKeySet`, `StoreSliceUpdate`, `Snapshot` — each object is an **object tree**: a DAG of signed, encrypted changes with periodic snapshots (`any-sync/commonspace/object/tree/objecttree`), validated against the space's ACL list (with read-key rotation on member removal).
- **any-sync network**: sync nodes (store spaces), file nodes, consensus nodes (ACL ordering), coordinator (config); DRPC over libp2p/QUIC, proto versioning with a ±1 compatibility window and a documented two-phase "prepare/activate" rollout (`docs/proto-versioning.md`); a 2026 **stateless pub/sub** for presence (`docs/stateless-pubsub.md`, explicitly modelled on NATS/Yjs-awareness). Self-hostable via `any-sync-dockercompose`.
- **Local API** (`core/api`, OpenAPI `2025-11-08`, gateway `127.0.0.1:31009`): `/v1/auth/challenges` → `/v1/auth/api_keys` (pairing: the app shows a 4-digit code), `/v1/search`, `/v1/spaces/{id}/{objects,types,properties,tags,lists/views,members,files,chats,search}`; objects expose a markdown body with patching. Official **anytype-mcp** and a headless **Anytype CLI** (2026). 
- **Mobile**: native Swift/Kotlin apps talking to the same Go middleware; full offline; P2P LAN sync.
- **Lessons**: (a) The object-tree-of-signed-changes + snapshots + ACL is the *correct* serverless multi-device design, and it costs a company years and a custom DB, FTS, and four node types — vrite should not attempt it; a single trusted server is a legitimate simplification. (b) Steal the **local API pairing flow** (challenge code → API key) for desktop/local integrations, and the **markdown-body-in-JSON** object shape for LLM APIs. (c) Types + relations is a good schema for "supertag-like" features. (d) Source-available licensing and non-file storage are the reasons it is not the community default despite excellent engineering.

## 6. TriliumNext

Repo: https://github.com/TriliumNext/Trilium (renamed from `Notes`) · docs: https://docs.triliumnotes.org · 37.8k★, 2.5k forks, AGPL-3.0, v0.105.0 (Aug 2026), 37.7k commits; community-stewarded after zadam. Protected notes are encrypted per note.
- **Sync** (`Concepts/Synchronisation.md`): every change writes an `entity_changes` row (`entityName, entityId, hash, changeId (uuid), componentId, instanceId, isSynced, utcDateChanged`). (b) One token for ETAPI and MCP, an OpenAPI spec, and MCP tools = internal AI tools is the right API discipline. (c) **The standalone build is the blueprint for vrite's "same TypeScript core on server and in the PWA"** — including the iOS service-worker caveat. (d) Avoid HTML-as-content and a heavyweight rich-text editor: no markdown files, hard export, huge client. (e) Attributes (labels + relations, inheritable) are a good, small property system.

## 7. Athens Research (and the Roam-clone lineage)

Repo: https://github.com/athensresearch/athens · 6.3k★, EPL-1.0, **"Athens is no longer maintained"**, last commit 2022-12-12; YC W21; export tool https://github.com/bshepherdson/athens-export (to Logseq markdown). Local clone: `scratchpad/repos/athens` (`doc/adr/` has 26 ADRs worth reading).

- **Stack**: ClojureScript + re-frame + reagent, **datascript** in memory, persisted as a transit dump (`index.transit`); Electron and web builds; a self-hosted "Lan-Party" Clojure server backed by a **Fluree** append-only event ledger.
- **Schema** (`src/cljc/athens/common_db.cljc`): `:block/uid` and `:node/title` unique identities, `:block/children` refs, `:block/refs` (maintained by a "linkmaker" from strings), `:block/order`, `:block/string`; v2 added properties as child blocks keyed by `:block/key` (tuple-unique per parent); v3 added `:event/*` and `:block/create`/`:block/edits` provenance.
- **Protocol** (ADR-010/013/014/018): UI intents were rewritten as a small vocabulary of **atomic graph ops** — `:block/new|save|open|move|remove`, `:page/new|rename|merge|remove`, `:shortcut/*` — composed into composite ops (e.g. paste). ADR-013 chose the **sequence of events as the source of truth** (state is derived; enables migration, replay, self-healing, offline). Clients send optimistic ops, the server produces the canonical stream and acks/rejects (a stale client is rejected rather than overwriting); ADR-014 admits each atomic op was transacted separately, "a lot of overhead… revisit when we take on CRDTs".
- **Durability failure** (discussion #1082): datascript-in-memory + client/server transaction ordering issues caused **data loss and inconsistent states**; the fix was ack-gated transactions and server-side resolution of side effects (ordering, refs).
- **Lessons**: (a) The atomic-op vocabulary *is* the right shape for an outliner's sync, undo, API and MCP surface (Workflowy's op log and Logseq DB's transactions converged on the same thing). (b) Never keep the source of truth only in memory with periodic dumps — persist every op to SQLite/append-only log first. (c) A VC-scale "collaborative knowledge graph" pivot, a niche language (CLJS), no mobile, and Roam-compat markdown all contributed to the death; the community migrated to Logseq/Obsidian. (d) Do write ADRs; Athens' are still useful three years after the project died.

## 8. Obsidian (closed) — plugin API and sync shape

*From the Obsidian sub-report; key sources: https://docs.obsidian.md, https://github.com/obsidianmd/obsidian-api, https://obsidian.md/blog/future-of-plugins/, https://obsidian.md/help/sync/security, https://github.com/coddingtonbear/obsidian-local-rest-api, https://obsidian.md/changelog/.*

Single typings package `obsidian` (one `obsidian.d.ts`, v1.13.1, peer-deps CM6). Plugins are unsandboxed (full DOM + Node).
- **Distribution**: GitHub release + directory entry; since May 2026 a developer dashboard with automated per-version review, safety scorecards, verified authors, Free/Paid labels. **~7.4k community plugins, 120M downloads.** Why it works: web stack + one stable `.d.ts`, plain files (no schema migrations), `MetadataCache` hands plugins parsed structure for free, GitHub-release distribution costs nothing, and "file over app" means plugins cannot lock users in.
- **Markdown design**: `.md` + `.obsidian/`; YAML **properties** (flat; no nested/inline values); `[[Note#Heading]]`, `[[Note#^blockid]]` — block ids are **written into the file**; **Bases** (1.9, 2025): `.base` YAML views (table/cards/list/map/kanban) over file properties. Limits: no outliner, no block-level metadata, per-device index rebuild in IndexedDB.
- **Obsidian Sync**: E2EE (AES-256-GCM, scrypt), only contents encrypted (paths/timestamps/hashes visible); **no CRDT** — markdown merged with diff-match-patch, everything else last-modified-wins, optional "Conflicted copy" files (1.9.7); 1–12 months version history; selective sync by type/folder; $4–8/mo. Mobile: full-vault indexing on startup is the perennial complaint; 1.14 added native "Quick Capture" that writes without loading the vault.
- **External APIs**: community **Local REST API** (`https://127.0.0.1:27124`, self-signed CA, Bearer key; `GET/PUT/POST/PATCH/DELETE /vault/{path}`, `/active/`, `/periodic/{period}/`, `/search/simple/`, `/search/` (JsonLogic/Dataview), `/tags/`, `/commands/`, and now `POST /mcp/`). Its **PATCH** with `Operation: replace|prepend|append|delete` × `Target-Type: heading|block|frontmatter`, `If-Match`, `Create-Target-If-Missing` is what LLM tools actually use (mcp-obsidian: 4.4k★). Official: `obsidian://` URIs, **Obsidian CLI** (1.12, Feb 2026, 100+ commands, JSON output, `eval` "for agentic coding tools"), Web Clipper, kepano's `obsidian-skills` (~48k★).
- **Timeline**: 1.9 Bases (May 2025), 1.10 Bases API, 1.11 mobile redesign + Keychain, 1.12 CLI (Feb 2026), 1.13 security guardrails + Settings API (May 2026), 1.14 Kanban + Quick Capture (Sep 2026). Free for commercial use since Feb 2025. CEO Steph Ango since 2023; ~3 engineers.
- **Lessons**: ship one `vrite.d.ts`, a template repo and in-app install from GitHub releases; expose the parsed index (links, backlinks, tags, blocks, properties) as a first-class API on both server and client; design the HTTP API around **surgical PATCHes** with `If-Match`; be explicit about merge semantics and offer conflict files; never index the whole vault on mobile startup and support quick capture without loading.

- **Foam**: TS monorepo (`foam-core`, `foam-vscode`, `foam-cli`, `foam-mcp`), 17.4k★, MIT, v0.44.6 (Sep 2026), one maintainer. ## 12. Cross-cutting conclusions

### 12.1 Top 10 design lessons for vrite (ranked)
1. **Server holds the truth *and* the index; the PWA holds a replica.** SilverBullet shows what happens when *all* logic is client-side (per-device re-index, headless-Chrome API hack); SiYuan/Trilium show that a kernel with one HTTP/WS API serving UI, plugins, CLI and MCP scales. Trilium's standalone build proves the same TypeScript core can also run inside the PWA on SQLite-WASM/OPFS for offline.
2. **Sync as a small idempotent op log at block granularity, not whole-file or full CRDT.** Workflowy's `push_and_poll`, Athens' atomic ops, Trilium's `entity_changes`, SiYuan's `doOperations` and Anytype's `changes.proto` all converge on `create/update/move/delete(block)` with ids, parent, order, client cursor, server transaction id. Do LWW per block with hashes and tombstones; keep a per-file 3-way-merge fallback (SilverBullet) for external edits to the markdown. Defer CRDT (SilverBullet tried and removed it; AFFiNE/Anytype show the cost).
3. **Markdown stays canonical; every index is a rebuildable cache** (SilverBullet ADR-003, SiYuan `temp/*.db`, Obsidian). Use SQLite + FTS5 from day one (Dendron's 30× lookup win, SiYuan's SQL); never JSON-per-block as the user-facing format (SiYuan's "no Dropbox" rule).
4. **Conflicts must be visible and never lossy**: ETag/`If-Match` on every write, 412 → merge, in-band conflict markers rendered as a widget, deletion never beats an edit (SilverBullet), optional conflict copies (Obsidian), conflict history retained (SiYuan dejavu).
5. **One extension language, one query language, one command registry.** SilverBullet's v2 lesson (three DSLs → Lua) and Tana's "every command is named and rebindable". For vrite: TypeScript plugins + one query DSL (SQL-shaped or Logseq-simple), commands in a palette.
6. **Plugin model = Obsidian ergonomics + SilverBullet isolation + SiYuan kernel plugins**: a single `vrite.d.ts`, `Plugin` class with auto-cleanup `register*` helpers, GitHub-release distribution and an in-app installer; client plugins in Web Workers behind a syscall boundary with manifest permissions; server plugins in worker threads that can register HTTP routes, indexers **and MCP tools** (SiYuan `agent.registerCapability`).
7. **API for LLMs = surgical patches + search + SQL + MCP on the same token**: Obsidian Local REST API's `PATCH` (heading/block/frontmatter targets, `If-Match`, `Create-Target-If-Missing`), SiYuan's `/api/query/sql` and block ops, Trilium's "MCP tools = internal AI tools, same ETAPI token", Foam/Roam's read-only-by-default scopes, Anytype's pairing flow for local clients. Publish an OpenAPI spec.
8. **Mobile is Workflowy, built like Trilium standalone**: PWA + optional Capacitor shell, offline replica, sticky breadcrumbs, zoom-into-node, keyboard toolbar row, swipe actions, read-mode lock, quick capture that never loads the whole graph (Obsidian's biggest complaint). Mind the iOS `capacitor://` service-worker trap.
9. **Namespaces**: store `A/B/C` in the title with a stable id, resolve `[[leaf]]` by shortest unambiguous suffix (Foam, SilverBullet ADR-011), display the short form, and ship Dendron-style lookup (fuzzy, Tab-per-level, create with stub parents) and refactor commands (rename/move/merge with link rewriting). Tags with light schemas (`key:: type` on the tag page) give 80% of Tana supertags in Logseq syntax.
10. **Scope discipline and ADRs.** Every dead or struggling project (Athens, Dendron, Roam, Tana's pivot, AFFiNE's 870k LOC) died of scope or business model, not lack of features; every healthy one (SilverBullet, Obsidian, Foam, Workflowy) is small, file-first and steadily released. Write ADRs — Athens' and SilverBullet's are still the most useful artefacts they produced.
