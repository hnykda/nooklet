# ADR 004: UUIDv7 ids and fractional-index ordering

Date: 2026-09-10. Status: accepted.

## Decision

- Pages, blocks, and devices get UUIDv7 ids (time-ordered, generated by the creating device).
  They are valid UUIDs, so Logseq-style `id::` properties and `((block refs))` keep working, and
  imported Logseq v4 ids are kept as-is.
- Sibling order is a fractional-index string (`fractional-indexing`), stored per block. No
  linked lists (Logseq's `left` pointer caused corruption bugs; Logseq DB also moved to
  fractional indexes).
- Page identity is the lowercased, NFC-normalized, whitespace-collapsed name. Namespaces are
  "/"-separated inside the name; ancestors are implied, never stored.

## Why

Per-block, independently mergeable attributes are what make last-writer-wins sync trivial; a
linked list makes every reorder touch two neighbours and is unmergeable.
